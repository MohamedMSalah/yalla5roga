# Service setup guide

The [environment reference](development/ENVIRONMENT_CONFIGURATION.md) lists every application variable and default. The [deployment runbook](development/PRODUCTION_DEPLOYMENT.md) covers release commands, backup, rehearsal, ingress and rollback.

Current profile policy (2026-11-23): reuse the existing cloud services in both profiles. Do not create extra Firebase projects, databases or buckets. Historical live-test evidence below predates this configuration change; this task performed offline checks only. See the environment reference for shared-service risks and missing release signing.

## Neon and Prisma

1. Sign in to Neon. Verify the existing production project, branch, role and database. For device or staging, create a branch in **Branches → Create branch** or use local PostgreSQL. Prefer an empty or sanitized branch with a distinct role. [Neon Console](https://console.neon.tech/) · [Branching](https://neon.com/docs/introduction/branching)
2. In **Connect**, copy the selected branch URL into `DATABASE_URL`. Disable pooling in the dialog to obtain the direct migration URL for `DIRECT_URL`. Use the direct hostname without `-pooler` for `EXPECTED_DATABASE_HOST` and database name for `EXPECTED_DATABASE_NAME`. Use separate runtime and migration roles where possible. The runtime needs application table, sequence and function access. Migration tooling needs schema ownership. Keep TLS verification enabled. [Neon connection guide](https://neon.com/docs/connect/connect-from-any-app) · [Prisma deployment](https://www.prisma.io/docs/orm/prisma-migrate/workflows/development-and-production)
3. Build the backend and run `node scripts/database-status.mjs production`. Take an encrypted backup, verify restore, and rehearse the actual pending SQL before an approved live deployment.
4. Neon's card-free plan lists 100 CU-hours and 1 GB per project. Branch count, restore window and egress have plan limits. Paid plans meter compute and storage. Prisma runs inside the existing application without a hosted proxy. [Neon pricing](https://neon.com/pricing)

## Firebase

1. In Firebase Console use the existing project for production and use the existing project for both primary profiles; do not add another project. Register the actual Android package and iOS bundle under **Project settings → General → Your apps**. Download `google-services.json` for the Android build variant and `GoogleService-Info.plist` for the iOS target. [Firebase Console](https://console.firebase.google.com/) · [Flutter setup](https://firebase.google.com/docs/flutter/setup)
2. Map Android `current_key` and `mobilesdk_app_id` to `FIREBASE_ANDROID_API_KEY` and `FIREBASE_ANDROID_APP_ID`. Map iOS `API_KEY`, `GOOGLE_APP_ID`, `BUNDLE_ID` and `CLIENT_ID` to the matching `FIREBASE_IOS_*` variables. Use the project ID, project number/sender ID, options bucket identifier and Google Web OAuth ID for `FIREBASE_PROJECT_ID`, `FIREBASE_MESSAGING_SENDER_ID`, `FIREBASE_STORAGE_BUCKET` and `FIREBASE_WEB_CLIENT_ID`. The options bucket identifier does not require a Cloud Storage subscription.
3. In **Authentication → Sign-in method**, enable Phone and Google, set support email and SMS regions, and add fictional test phone numbers and codes. Register SHA-1 and SHA-256 fingerprints for the intended debug, release and Play signers. Refresh the platform configuration after changing registrations. Check the server Auth key and restricted mobile keys separately. [Phone Auth](https://firebase.google.com/docs/auth/flutter/phone-auth) · [Google sign-in](https://firebase.google.com/docs/auth/flutter/federated-auth) · [Firebase API keys](https://firebase.google.com/docs/projects/api-keys)
4. In **Project settings → Service accounts** or Google Cloud IAM, use a backend principal scoped for Auth administration and FCM send. Auth permissions must cover lookup, identity updates, disable/delete and revocation. Copy `client_email` and `private_key` into `FIREBASE_CLIENT_EMAIL` and `FIREBASE_PRIVATE_KEY`. Set `EXPECTED_FIREBASE_PROJECT_ID` independently. Set `FIREBASE_API_KEY` to the same project's key allowed for server Auth exchange. Enable the FCM v1 API. [Admin setup](https://firebase.google.com/docs/admin/setup) · [FCM permissions](https://firebase.google.com/docs/cloud-messaging/auth-server)
5. Upload the matching APNs key and identifiers via **Project settings → Cloud Messaging → Apple app configuration** when shipping iOS. Keep the APNs key with Apple/Firebase administration. On Android, allow notifications and verify token registration and foreground, background and terminated delivery. Check Analytics DebugView, Crashlytics reports and Performance traces in the existing shared project; local telemetry is live project telemetry. [Flutter FCM setup](https://firebase.google.com/docs/cloud-messaging/flutter/client) · [Analytics](https://firebase.google.com/docs/analytics/debugview) · [Crashlytics](https://firebase.google.com/docs/crashlytics/get-started?platform=flutter) · [Performance](https://firebase.google.com/docs/perf-mon/flutter/get-started)
6. Test token refresh, recovery, revocation, account synchronization and deletion with disposable identities. Established sockets recheck every 30 seconds with a five-second deadline. Budget about two revocation lookups per minute per active socket plus handshakes, reconnects and production authenticated HTTP calls. [Session management](https://firebase.google.com/docs/auth/admin/manage-sessions)
7. Analytics, Crashlytics, Performance and FCM are no-cost products with feature limits. FCM documents a 600,000 downstream messages/minute default quota. Real phone SMS requires Blaze billing and is billed per SMS. Firebase fictional test numbers exercise Auth without sending SMS. Apple distribution has separate program terms. [Firebase pricing](https://firebase.google.com/pricing) · [Auth limits](https://firebase.google.com/docs/auth/limits) · [FCM quotas](https://firebase.google.com/docs/cloud-messaging/throttling-and-quotas) · [Apple Developer](https://developer.apple.com/programs/)

## Cloudflare R2

1. In **Storage & databases → R2 → Overview**, activate R2 and create a Standard private bucket per environment. Keep public development URLs and custom domains disabled on private buckets. Populate `R2_ACCOUNT_ID` and `R2_BUCKET_NAME` plus `EXPECTED_R2_ACCOUNT_ID` and `EXPECTED_R2_PRIVATE_BUCKET` for hosted deployment. [Cloudflare dashboard](https://dash.cloudflare.com/) · [R2 setup](https://developers.cloudflare.com/r2/get-started/)
2. Under **Manage R2 API tokens**, create an **Object Read & Write** credential scoped to the exact buckets. Put the Access Key ID and Secret Access Key in `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY`. `R2_ENDPOINT` overrides the default account endpoint. [R2 tokens](https://developers.cloudflare.com/r2/api/tokens/)
3. Configure an object expiration rule for the private `uploads/` prefix only, for example after one day. This catches staged data replayed before a presigned URL expires and interruptions during cleanup. Native uploads use signed headers. If a browser client will use these endpoints, restrict bucket CORS to authorized origins and the needed methods and headers. [Lifecycle rules](https://developers.cloudflare.com/r2/buckets/object-lifecycles/) · [CORS](https://developers.cloudflare.com/r2/buckets/cors/)
4. For a public catalog, create a separate bucket and attach its HTTPS custom domain. Set `R2_PUBLIC_BUCKET_NAME`, `EXPECTED_R2_PUBLIC_BUCKET` and `R2_PUBLIC_BASE_URL`. Inspect existing object paths and CDN caches before changing any route or domain. Set `PLACES_CURATOR_UIDS` for curator access and `PLACE_IMAGE_SOURCE_HOSTS` for exact allowed HTTPS image hosts. [Public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/)
5. Use disposable objects to test private PUT, pre-confirm denial, server promotion to a different key, malformed-object rejection, signed owner GET, outsider denial, expiry and deletion. Verify anonymous private object URLs and public-origin requests deny access. Verify public catalog cache headers and legacy ready image links. [Presigned URLs](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)
6. Standard includes 10 GB-months, 1 million Class A and 10 million Class B operations monthly. Overage is metered and internet egress is free. A successful upload adds HEAD, bounded GET, final PUT and cleanup operations. R2 signup uses Cloudflare checkout, and domain registration is separate. [R2 pricing](https://developers.cloudflare.com/r2/pricing/)

An approved one-image import can use `pnpm project device tsx scripts/import-catalog-image.ts <curator-uid> https://images.example.org/photo.jpg`. Select `production` only for an approved hosted import. Attach the returned reference using the existing curator place-image endpoint. The importer accepts only allowlisted hostnames, pins a public DNS answer, rejects redirects and optimizes before storage. Existing ready images and catalog backfills require separate operator work.

For an approved backfill, inventory existing ready catalog references and original licenses. Rehearse a representative batch against the isolated catalog bucket. Verify each new CDN image and its metadata before changing the corresponding place record. Record the old reference so it can be restored if delivery fails, and retain the old object until the replacement and cache behavior have been checked.

## WhatsApp

1. Try the normal share action with both languages, confirm the normalized phone and group reference, and test the existing copy fallback. A verified registration claims an invitation as pending. The recipient must still accept or decline. Click-to-chat requires no Meta developer account. [WhatsApp help](https://faq.whatsapp.com/5913398998672934)
2. For optional automation, create a Meta business portfolio and developer app with WhatsApp. In **WhatsApp → API Setup**, choose the sandbox or production sender and copy the Phone Number ID into `WHATSAPP_PHONE_NUMBER_ID`. In **Business Settings → System Users**, assign the asset and issue a token with `whatsapp_business_messaging` for `WHATSAPP_ACCESS_TOKEN`. Use `whatsapp_business_management` for separate management tasks. Set `WHATSAPP_PROVIDER=meta` and a supported `WHATSAPP_API_VERSION`. [Meta dashboard](https://developers.facebook.com/apps/) · [Cloud API setup](https://developers.facebook.com/documentation/business-messaging/whatsapp/get-started)
3. In WhatsApp Manager approve group and special-event templates. The group body expects inviter, group and deep link. The event body expects title, date/time, venue, calendar URL and app URL. Set `WHATSAPP_INVITE_TEMPLATE`, `WHATSAPP_SPECIAL_EVENT_TEMPLATE` and `WHATSAPP_INVITE_TEMPLATE_LANG`. Automation uses one template language per environment. No inbound webhook is implemented or required for outbound acceptance. Use opted-in sandbox recipients only for verification. [Meta templates](https://developers.facebook.com/documentation/business-messaging/whatsapp/templates/overview)
4. Meta offers test senders in setup. Production template delivery can be charged by category and destination market. Review the rate card and billing before enabling Meta. [WhatsApp pricing](https://developers.facebook.com/documentation/business-messaging/whatsapp/pricing)

## Maps, catalog and geocoding

- **MapLibre and OpenFreeMap.** The default public endpoint takes no credential. OpenFreeMap's offline policy allows up to 3,000 tiles or 50 MB per download, four parallel requests and a unique User-Agent. The app estimates a 2,500-tile/45-MiB maximum per pack and configures four concurrent requests. Confirm actual transferred bytes, attribution, offline eviction and lost-network behavior before public release. For a different provider, configure the documented `MAP_*` URLs and enable offline only with permission. Hosting your own tiles incurs infrastructure costs. [MapLibre](https://maplibre.org/) · [OpenFreeMap setup and offline policy](https://openfreemap.org/quick_start/)
- **Pelias.** Deploy or select an authorized instance supporting `/v1/autocomplete` and `/v1/reverse`, set `GEOCODING_PROVIDER=pelias`, `GEOCODING_BASE_URL`, `GEOCODING_ATTRIBUTION` and optional `GEOCODING_API_KEY`. Verify timeout and fallback behavior from isolated Swagger. The open-source software has no per-call license fee. Managed service and infrastructure limits vary. Public Nominatim autocomplete and bulk OSM raster downloads are outside the configured paths. [Pelias Docker](https://github.com/pelias/docker) · [Nominatim policy](https://operations.osmfoundation.org/policies/nominatim/) · [OSM tile policy](https://operations.osmfoundation.org/policies/tiles/)
- **Catalog.** Geofabrik Egypt OSM extracts and Overture STAC provide existing public ingestion inputs. The optional Overpass endpoints enforce their own fair-use limits. These paths need no project token. Use local extracts for bulk work, respect data licenses, and check target and attribution before operator imports. App startup does not run bulk import. [Geofabrik](https://download.geofabrik.de/africa/egypt.html) · [Overture](https://docs.overturemaps.org/getting-data/) · [Overpass](https://wiki.openstreetmap.org/wiki/Overpass_API)
- **GPS, SQLite and place photos.** Verify permissions, inaccurate fixes, screen visibility, cache-first viewport loads, cancellation and offline recovery. Verify private custom places stay in owner-scoped SQLite across account switches and that cached or missing images retain fallback behavior. No GPS service credential is used. [Android location permissions](https://developer.android.com/develop/sensors-and-location/location/permissions)

## Hosting, monitoring and related services

- **Hosting.** Choose a Linux host that supports a long-running Node process, TLS, WebSockets and graceful shutdown. Configure DNS, certificate, ingress address, service recovery, secret injection and private health/metrics there. Cost depends on instance, egress, storage and DNS. Let's Encrypt provides free certificates for a controlled domain. [Deployment runbook](development/PRODUCTION_DEPLOYMENT.md) · [Socket.IO proxy](https://socket.io/docs/v4/reverse-proxy/) · [Let's Encrypt](https://letsencrypt.org/getting-started/)
- **Monitoring.** Generate a separate monitoring bearer and set `MONITORING_TOKEN`. Provide `GRAFANA_ADMIN_PASSWORD` to Compose and keep Grafana, Prometheus and private metrics internal. The OSS servers require no SaaS account. Host compute and storage still apply. [Monitoring commands](development/OBSERVABILITY.md) · [Prometheus](https://prometheus.io/docs/introduction/overview/) · [Grafana OSS](https://grafana.com/oss/grafana/)
- **App links and Shorebird.** Publish `/.well-known/assetlinks.json` with the actual Android package and signing fingerprints and Apple's association file with the team and bundle pairing if shipping iOS. Existing Shorebird metadata requires a valid Shorebird project only if using that release tool. [Android App Links](https://developer.android.com/training/app-links/verify-android-applinks) · [Apple associated domains](https://developer.apple.com/documentation/xcode/supporting-associated-domains) · [Shorebird Console](https://console.shorebird.dev/) · [Shorebird pricing](https://shorebird.dev/pricing/)
- **Fonts and calendar.** Google Fonts uses the app's existing package and caching behavior. Calendar URLs open the user's calendar UI without a server-side calendar integration. [Google Fonts](https://developers.google.com/fonts/faq)
- **Unused.** Application records and photo bytes use Neon and R2. No runtime Firestore, Realtime Database, Firebase Storage, hosted Prisma proxy, public Nominatim, commercial Places API, external image compression API or Cloudflare Images account is required.

# Database schema audit

Live catalog captured 2026-11-10T13:44:28.060Z. The table and column decisions describe the final deployed schema. The reference appendix records the removed fields.

Target: project `rough-mountain-69896781`, branch `br-fragrant-heart-avfm4h2t`, database `neondb`, endpoint `ep-misty-glitter-av3zwlzf.c-11.us-east-1.aws.neon.tech`. Owner-supplied project and branch names are neon-pink-ladder / main. The SQL connection independently returned the IDs shown here.

Scope: 23 application tables plus Prisma history; every scalar column, PK, FK, unique index, ordinary/partial index, check/default/nullability and enum inspected. Source evidence is in `docs/audit/database/source-usage.json`; exact definitions are recorded in the catalog snapshots under `docs/audit/database/`. Zero rows is not evidence that an approved feature is obsolete.

The approved flow is phone/password login and phone OTP verification at signup. No table is proposed for removal or merger: all application tables support an active approved feature/API, and outbox, logs, attendance, arrivals and votes have distinct semantics. No unused asset/user-alias table is added.

KEEP all columns and records; never reset or rewrite migration history.

### chat_messages

REST persists once and Socket.IO delivers after commit. client_message_id provides idempotency. The (outing_id, sent_at DESC, id DESC) index covers history ordering and replaces the shorter index.
